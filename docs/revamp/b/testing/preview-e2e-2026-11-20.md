## Findings

### F1 ❌ Workspace tutors have no tutor profile, so the teaching pages stop

Signed in as `seed.ubuntu.owner`, these pages show only "No tutor profile
found for this account." (or "No student profile…" on `/dashboard/courses`):
dashboard home, courses, manage courses, tests and grading, gradebook,
assignments, schedule, analytics.

Why: B's pages start from the old `Tutor` row (`prisma.tutor.findUnique({
where: { email } })`, about 23 files), and the tenancy filters in
`tenancy-where.ts` take a Tutor profile id. Accounts made the tenancy way
(the seed, `createWorkspace`, the new role choice) get a Membership but no
`Tutor` row. Students are fine because `chooseRoleFor` and the seed make a
`Student` row. Real tutors from before tenancy still have their `Tutor` row,
so production isn't affected today, but every new tutor would be.

Work fine for the owner: fees, settings, profile, notifications, the 404
page (1.11 ✅).

### F2 ❌ Better Auth on Preview refuses every sign-in (A, #175)

After Preview switched to Better Auth, signing in on this branch's Preview
showed "Please verify your email address first." The real answer is 403
`INVALID_ORIGIN`, on both the branch alias and the per-commit URL, before
any password check. The 19 seed accounts are verified, and each has a
credential account (count-only read). A's sign-in helper shows every 403 as
the verification message. Raised with A, with the owner's request to let
chosen test accounts skip verification on Preview.

### F3 ⚠️ Owners see only the courses they teach

On the PR 171 alias, the owner's course list holds only her own course,
not tutor1's or tutor2's. The list filters by "taught by this user". For an
owner or admin it should probably show every course in the workspace
(read-only where they don't teach). Follow-up for B.
